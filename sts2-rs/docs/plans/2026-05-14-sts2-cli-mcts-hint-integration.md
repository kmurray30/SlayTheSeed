# sts2-cli ⇄ sts2-rs MCTS hint integration — design spec

**Date:** 2026-05-14
**Status:** approved (brainstorming complete; pending writing-plans)
**Owner:** sts2-rs (this repo) — sts2-cli changes tracked here for coordination
**External project:** `~/projects/sts2/sts2-cli` (Python 3.13 + uv, MCP server, plays against `Sts2Headless` C# binary)

## Goal

When a human plays a combat through `sts2-cli` (CLI prompt or MCP `recommend_combat` tool), surface MCTS hints from sts2-rs as inline annotations on the numbered action choices. The C# `Sts2Headless` engine remains authoritative; sts2-rs runs as a same-process hint sidecar via the existing `sts2_rs` PyO3 module.

## Non-goals

- Replacing `Sts2Headless` as the play engine.
- Synchronising RNG streams between Sts2Headless and sts2-rs (we accept rollout divergence for hint ranking).
- A PyPI release of `sts2_rs` — local maturin build only (tracked separately under bead `sts2-rs-3lo`).
- Hinting on game phases other than combat (run/map layer not ported yet — see P9 plan).

## Architecture

```
┌─ sts2-cli (Python) ────────────────┐    ┌─ Sts2Headless (C# .NET) ─┐
│ play.py REPL                       │◄──►│ Real STS2 engine          │
│  ├── sts2_client.Game (existing)   │JSON│ (subprocess, JSON/stdio)  │
│  ├── show_combat() rendering       │    └───────────────────────────┘
│  └── NEW: sts2_hint/                │
│       ├── adapter.py  (dict → sts2_rs)
│       ├── recommender.py            │   import sts2_rs (PyO3 module)
│       └── display.py                │──►┌─ sts2_rs (Rust, in-proc) ──┐
└─────────────────────────────────────┘   │ PyCombatState + Mcts       │
                                          │ NEW: state_from_dict()     │
                                          │ NEW: mcts_recommend()      │
                                          │ NEW: UnsupportedStateError │
                                          └────────────────────────────┘
```

- Same-process. No new subprocess, no new IPC.
- sts2-rs is loaded as a regular Python dep via `maturin develop` from `crates/sts2-py`.
- Sts2Headless remains authoritative; its JSON state snapshot is fed into sts2-rs each turn.

## State-transfer schema

Canonical contract — typed Python dict that the Python adapter builds and the Rust `state_from_dict` consumes.

```python
{
  "rng": {"seed": int, "ascension": int},
  "player": {
    "class": "ironclad" | "silent" | "defect" | "necrobinder" | "regent",
    "hp": int, "max_hp": int,
    "block": int,
    "energy": int, "max_energy": int,
    "relics": [str, ...],                       # canonical relic IDs
    "powers": [{"name": str, "amount": int}, ...],
    "potions": [str | None, str | None, str | None],
  },
  "deck": {
    "draw_pile":    [CardSpec, ...],            # CardSpec = {"id": str, "upgraded": bool, "cost_override": int | None}
    "discard_pile": [CardSpec, ...],
    "hand":         [CardSpec, ...],
    "exhaust_pile": [CardSpec, ...],
  },
  "encounter": [
    {"kind": str,                                # canonical MonsterKind ID
     "hp": int, "max_hp": int, "block": int,
     "powers": [{"name": str, "amount": int}, ...],
     "intent_history": [int, ...]},
    ...
  ],
  "turn": int,
  "combat_id": int,
}
```

### Sources of truth

- **Rust side (canonical):** `crates/sts2-py/src/state_dict.rs` defines parsing + validation.
- **Python mirror:** `~/projects/sts2/sts2-cli/python/sts2_hint/schema.py` re-declares the same structure as a `TypedDict` for static checking.
- **JSON-schema dump:** `docs/sts2-hint-state-schema.json` (generated by `cargo run -p sts2-py --example dump_state_schema`) for cross-language CI checks.

### Fail-loud rule

`state_from_dict()` raises `sts2_rs.UnsupportedStateError("<path>: <value>")` and aborts on ANY of:

- Unknown relic ID (not present in `RelicKind` registry).
- Unknown card ID (not present in `CardKind` registry).
- Unknown monster kind (not present in `MonsterKind` registry).
- Unknown power name.
- Player class not in the ported set (Ironclad fully, Silent/Defect partial, Necrobinder/Regent in flight).
- Schema violations: HP > max_hp, energy < 0, deck sizes inconsistent with turn invariants, etc.

The Python side catches the exception, logs to `sts2-cli/logs/hint-errors.log` with the offending state path, and renders the combat **without hint tags**. Combat itself never crashes from a hint failure.

## Hint orchestration

New Python module `sts2-cli/python/sts2_hint/`:

| File | Responsibility |
|---|---|
| `adapter.py` | Reads `sts2_client.Game` state, normalises it into the schema above, calls `sts2_rs.state_from_dict()`. Sole owner of the C#-state → Rust-state translation. |
| `recommender.py` | Calls `sts2_rs.mcts_recommend(state, sims=…, c_puct=…, depth=…, seed=…, threads=…)`. Returns `[(action_index, win_prob, sims_used, pv_summary), ...]`. |
| `display.py` | Bucketises win-prob (reusing the bucketing constants from sts2-rs `crates/sts2-mcts/src/hint.rs`). Formats inline tags. |
| `schema.py` | `TypedDict` mirror of the Rust schema. |
| `errors.py` | Catches `UnsupportedStateError`, appends to log, returns empty annotation map. |

### Integration point in `play.py`

```python
# in show_combat(game), just before rendering numbered choices:
tags = sts2_hint.annotate(game, cfg=hint_cfg)   # {stable_idx: HintTag} or {} on failure
for idx, card in stable_hand.iter():
    tag = tags.get(idx, "")
    print(f"  {idx}) {card.name:<20} {tag}")
```

`HintTag` rendering: `[WIN 62%] ▲` for best, `[WIN 41%]` for others, `[BAD 18%] ▼` for worst. Bucket thresholds inherited from sts2-rs (do not duplicate constants).

## sts2-rs new surfaces

In `crates/sts2-py/src/lib.rs` (and a new sibling `state_dict.rs`):

1. `state_from_dict(d: &PyDict) -> PyResult<PyCombatState>` — fail-loud adapter.
2. `PyCombatState.to_dict() -> PyDict` — round-trip counterpart, primarily for tests.
3. `mcts_recommend(state, *, sims, c_puct, depth, seed, threads) -> List[ActionScore]` — convenience that runs an independent MCTS per legal action.
4. `UnsupportedStateError` exception type registered with PyO3 (subclass of `ValueError`).

No engine logic changes — these are pure wrappers over existing core/mcts surfaces.

### `ActionScore` shape

```python
{
  "action": <action-dict from existing action_to_pydict>,
  "win_prob": float,        # [0.0, 1.0]
  "win_prob_bucket": str,   # "WIN" | "OK" | "BAD" from sts2-mcts/hint.rs
  "sims_used": int,
  "pv": [<action-dict>, ...],  # principal variation (depth ≤ 5)
  "is_best": bool,
}
```

## CLI surface

New flags on `play.py`:

| Flag | Default | Notes |
|---|---|---|
| `--mcts-sims N` | 300 | Per memory note: MCTS knee 300–3000. |
| `--mcts-depth D` | 10 | Per memory note: depth=200 over-rolls; depth=10 is +5-25% margin. |
| `--mcts-c-puct F` | 1.4 | |
| `--mcts-seed N` | 0 (derive from combat seed) | |
| `--mcts-threads N` | 1 | Reuses sts2-mcts parallelism. |
| `--no-hints` | false | Disables the hint sidecar entirely. |
| `--hint-on-demand` | false | Suppress inline tags; expose `/hint` REPL verb that runs one hint pass. |

Same flags accepted as MCP server config so the `recommend_combat` tool can serve hints with the same plumbing.

## Testing

| Layer | Test |
|---|---|
| Rust round-trip | `crates/sts2-py/tests/round_trip.rs`: 1000 random states → `to_dict()` → `state_from_dict()` → assert equal. |
| Rust fail-loud | One fixture per `UnsupportedStateError` path (unknown relic, unknown card, unknown monster, unknown power, schema violation × 4). |
| Python adapter | `sts2-cli/tests/test_hint_integration.py`: 5 hand-picked Sts2Headless JSON snapshots → adapter → MCTS hint non-empty + best action sane. |
| Smoke gate | sts2-cli plays 50 random Ironclad-vs-Cultist combats with `--mcts-sims=300`. Assert zero `UnsupportedStateError`. Wire into sts2-cli CI. |

## Build & packaging

- Add `maturin develop --release -m ../sts2-rs/crates/sts2-py/Cargo.toml` to `sts2-cli/setup.sh`.
- `sts2-cli/pyproject.toml` gains `sts2-rs @ file:///<checkout>/sts2-rs` as a local path dep.
- Document in `sts2-cli/README.md`. PyPI release stays out of scope.

## Known risks (called out, not solved)

1. **Schema completeness.** sts2-rs hasn't ported every relic/monster yet — fail-loud means many real combats get no hint early on. Acceptable; the gap shrinks as P6/P7 land.
2. **RNG divergence between engines.** Even with full state injection, MCTS rollouts diverge from C# reality. Acceptable for *ranking* — hint accuracy is relative, not absolute. Will be documented in `docs/known_divergences.md`.
3. **Per-action MCTS cost.** Independent MCTS per legal action × 5–10 actions × 300 sims ≈ 1.5–3 s/turn at current 145 searches/sec. Probably fine for human play; `--mcts-threads` mitigates. Async fallback deferred unless feedback says otherwise.
4. **Cross-repo build coupling.** Local path dep ties sts2-cli to a specific sts2-rs checkout. Dev-only, no CI implications.

## Implementation slicing (preview — fleshed out by writing-plans)

1. **Schema + adapter (Rust)** — `state_dict.rs`, `state_from_dict`, `to_dict`, `UnsupportedStateError`, round-trip tests.
2. **mcts_recommend** — convenience wrapper + `ActionScore` shape + Python tests.
3. **sts2-cli/sts2_hint module** — schema mirror, adapter, recommender, display, errors. Adapter is the heaviest piece.
4. **play.py wire-up** — show_combat hook, flags, `/hint` verb.
5. **MCP tool wire-up** — feed hints into `recommend_combat`.
6. **Smoke gate** — 50-combat zero-error CI check on sts2-cli side.
7. **Docs** — known-divergences entry, sts2-cli README, schema JSON dump.

Each slice becomes one or two beads in the writing-plans step.
